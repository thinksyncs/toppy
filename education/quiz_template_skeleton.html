Q1: Which transport does HTTP/3 use? Q1: HTTP/3 のトランスポートはどれ？

Multiple Choice 択一
Explanation: 解説:

HTTP/3 is the mapping of HTTP semantics onto QUIC. QUIC is the transport protocol (built on top of UDP) that provides stream multiplexing and integrates TLS 1.3, which is why HTTP/3 does not use TCP.

HTTP/3 は「HTTP を QUIC 上にマッピングしたもの」です。QUIC は UDP 上に構築されたトランスポートで、 多重化や TLS 1.3 の統合などを提供するため、HTTP/3 は TCP を使いません。

ATCP is used by HTTP/1.1 and most HTTP/2 deployments; avoiding TCP head-of-line blocking is a key reason QUIC exists.TCP は HTTP/1.1 や多くの HTTP/2 で使われます。TCP の HOL（先頭行）ブロッキング回避が QUIC の理由の 1 つです。
BCorrect: HTTP/3 runs over QUIC.正解: HTTP/3 は QUIC 上で動作します。
CHTTP/2 is an HTTP version (application layer), not a transport; it typically runs over TCP.HTTP/2 は HTTP のバージョン（アプリ層）で、トランスポートではありません。通常 TCP 上で動きます。
DWebSocket is an application protocol upgrade (usually over TCP); it is not the transport for HTTP/3.WebSocket は（多くの場合 TCP 上の）アプリ層の通信方式で、HTTP/3 のトランスポートではありません。

Q3: CONNECT-UDP is defined using which HTTP feature? Q3: CONNECT-UDP はどの HTTP 機能を使う？

Multiple Choice 択一
Explanation: 解説:

CONNECT-UDP is built on Extended CONNECT: the client uses HTTP’s CONNECT method with a :protocol value (e.g., udp) to create a tunnel-like association. In HTTP/3, the actual UDP payloads are carried using HTTP Datagrams.

CONNECT-UDP は Extended CONNECT を土台にしています。HTTP の CONNECT と :protocol（例: udp）を使ってトンネル状の関連付けを作り、HTTP/3 では UDP の ペイロードを HTTP Datagrams で運びます。

ACorrect: CONNECT-UDP is specified via Extended CONNECT.正解: CONNECT-UDP は Extended CONNECT を使って定義されています。
BWebSocket is a different protocol upgrade for message-based streams; it is not CONNECT-UDP.WebSocket は別のアップグレード方式で、CONNECT-UDP ではありません。
CREST is an API design style, not a protocol feature used to define CONNECT-UDP.REST は API 設計スタイルで、CONNECT-UDP を定義する HTTP 機能ではありません。
DSSE is server-to-client streaming over HTTP; it does not provide UDP tunneling.SSE はサーバ→クライアントのストリーミングで、UDP トンネリング用途ではありません。

ACorrect: UDP payloads are tunneled over HTTP/3 using CONNECT-UDP + HTTP Datagrams.正解: CONNECT-UDP + HTTP Datagrams で HTTP/3 上に UDP を運びます。

CICMP is not what CONNECT-UDP is for; doctor may do “ping-like” checks, but ICMP is not tunneled here.ICMP は CONNECT-UDP の用途ではありません（doctor の疎通確認はあっても ICMP をトンネルするわけではありません）。

Q5: HTTP Datagrams in toppy are used for ___. Q5: toppy の HTTP Datagrams の用途は？

Multiple Choice 択一
Explanation: 解説:

HTTP Datagrams provide an unreliable datagram delivery mechanism in HTTP/3. In toppy’s CONNECT-UDP flow, they carry the UDP payload bytes end-to-end between the CLI and the gateway.

HTTP Datagrams は HTTP/3 における “非信頼データグラム” 搬送の仕組みです。toppy の CONNECT-UDP では、 UDP のペイロードを CLI とゲートウェイ間でそのまま運びます。

ACorrect: used to deliver UDP payloads (datagram-style) for CONNECT-UDP.正解: CONNECT-UDP の UDP ペイロードをデータグラムとして運びます。
BTLS certificates are exchanged during the TLS handshake, not “downloaded” via HTTP Datagrams.TLS 証明書は TLS ハンドシェイクでやり取りされ、HTTP Datagrams で “ダウンロード” するものではありません。
CMetrics are typically exported via HTTP requests or telemetry protocols, not HTTP Datagrams.メトリクスは通常 HTTP リクエストやテレメトリで送ります。HTTP Datagrams の用途ではありません。
DFile uploads are better served by reliable streams; HTTP Datagrams are intentionally unreliable.ファイルアップロードは信頼性が必要なためストリーム向きです。HTTP Datagrams は意図的に非信頼です。
